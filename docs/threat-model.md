# Threat model

What the workbench service protects, from whom, and what is still open. Written for the 1.1.0 code;
nobody independent has reviewed it. The lab's own research scope is in [SECURITY_SCOPE.md](../SECURITY_SCOPE.md).

## What it protects

| Asset | Where it lives |
|---|---|
| Runs: restore matrices, probe results, minimized selections, reports, hash manifests | the data directory (`/data` in the image) |
| Fixture snapshots (synthetic identity, permission and secret stores) | created per run inside the run folder |
| Native OpenBao evidence | CLI output folders; the server never starts OpenBao |
| API keys | callers hold the key; the server holds only SHA-256 hashes |

## Trust boundaries

1. **Browser or script → server.** Request bodies are untrusted JSON and are validated before a run.
2. **Server → filesystem.** Run IDs are generated by the server and resolved inside the data directory.
3. **CLI → OpenBao.** The native adapter runs a separately verified OpenBao binary on loopback only.

## Threats and what stops them

| Threat | Mitigation | Residual risk |
|---|---|---|
| Another site's page drives the workbench (CSRF, DNS rebinding) | `Host` must be loopback or listed in `ALLOWED_HOSTS`; POSTs with a foreign `Origin` are refused; JSON only | — |
| Someone on the network reads runs or starts experiments | Hashed API keys with roles; production refuses to start without them; no public bind without keys | Every key sees every run (single tenant) |
| Flooding or a long matrix ties up the server | 1 MiB bodies with Content-Length, no chunked bodies, one experiment at a time (409), bounded matrix size and repeats, rate limit per client, 15 s socket timeout | One heavy run still blocks others by design |
| A request escapes the runs directory | Server-generated run IDs; path checks in case lookup | — |
| A bundle is altered after export | SHA-256 manifest checked by `verify` | The manifest is unsigned |
| Results leak into logs | Access logs are JSON with method, route, status and user only | — |
| Misreading a result | Reports separate `status` (expectation met) from the observed security outcome | — |

## Not covered

- Multi-tenant isolation between keys.
- Running OpenBao experiments through the web service.
- TLS (terminate it at the ingress).
